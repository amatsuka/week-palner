# week-palner

Однофайловый недельный планировщик задач (`index.html`, ванильный JS, без
сборки). Работает офлайн через `localStorage`; при желании синхронизируется
между устройствами через Supabase (magic link по email + Postgres с RLS).

В репозитории **нет никаких личных данных**: ни ролей, ни задач, ни плана.
При первом открытии палитра ролей пуста — всё (роли, задачи и, опционально,
сам план) загружается одним JSON-файлом через кнопку «Импорт JSON». Формат —
см. «Импорт ролей, задач и плана» ниже.

Подробности реализации — [docs/spec.md](docs/spec.md).

## Быстрый старт без Supabase

Открыть `index.html` (после деплоя — по адресу GitHub Pages, см. ниже; для
локальной проверки можно просто открыть файл напрямую, сеть не нужна). Без
входа приложение полностью работает локально, план хранится в `localStorage`
браузера. Нажать «Импорт JSON» и загрузить свой файл с ролями/задачами/планом.

## Импорт ролей, задач и плана

Единый JSON-файл, который загружается через «Импорт JSON»:

```json
{
  "roles": [
    {
      "id": "r1",
      "name": "Название роли",
      "color": "var(--r1)",
      "tasks": [ { "id": "task-id", "name": "Название задачи" } ]
    }
  ],
  "blocks": [
    { "task": "task-id", "day": 0, "minutes": 30 }
  ]
}
```

- `roles` — обязателен при первом импорте (пока ролей нет, палитра пустая и
  показывает подсказку). Сохраняется в `localStorage` браузера (ключ
  `week-planner-roles`) — переживает перезагрузку. При входе в аккаунт роли
  тоже синхронизируются через Supabase (таблица `role_configs`, отдельно от
  плана), так что на новом устройстве достаточно один раз войти тем же email —
  повторно импортировать JSON с ролями не нужно. Без входа роли остаются
  только локальными, как и план.
  `color` — любая доступная в CSS ссылка на цвет, например `var(--r1)`…`var(--r6)`
  из палитры в `<style>`, либо свой `#rrggbb`.
- `blocks` — план, необязателен. Можно импортировать только `roles` (тогда
  появится палитра, но неделя останется пустой), только `blocks` (если роли
  уже загружены раньше) или оба поля сразу.
- Кнопка «Экспорт JSON» отдаёт файл в этом же расширенном формате (с
  `roles` и `blocks` вместе) — удобно как разовый бэкап или перенос без
  Supabase.

## Подключение Supabase (синхронизация между устройствами)

1. **Создать проект.** На https://supabase.com — New project. Понадобится
   пароль от БД (не используется в коде, только для панели).

2. **Прогнать схему.** В панели проекта: SQL Editor → New query → вставить
   содержимое [supabase/schema.sql](supabase/schema.sql) → Run. Создаст
   таблицу `plans` (план, уникальный индекс `(user_id, week)`) и таблицу
   `role_configs` (роли/задачи, одна строка на пользователя), в обеих — RLS-
   политики и триггер `updated_at`.

3. **Взять URL и anon-ключ.** Project Settings → API:
   - `Project URL` → это `SUPABASE_URL`;
   - `anon public` ключ (не `service_role`!) → это `SUPABASE_ANON_KEY`.

4. **Настроить redirect URL для magic link.** Authentication → URL
   Configuration → Redirect URLs — добавить точный адрес страницы на GitHub
   Pages, например `https://amatsuka.github.io/week-palner/`.
   Email-провайдер (Email OTP / magic link) в Supabase Auth включён по
   умолчанию, дополнительно ничего включать не нужно.

5. **Вписать конфиг в `index.html`.** В начале `<script type="module">`
   найти блок:

   ```js
   const CONFIG = {
     SUPABASE_URL: "https://YOUR-PROJECT-REF.supabase.co",
     SUPABASE_ANON_KEY: "YOUR-ANON-PUBLIC-KEY",
     REDIRECT_TO: "https://amatsuka.github.io/week-palner/",
     WEEK: "2026-W37",
     START: "2026-09-07",
   };
   ```

   Заменить `SUPABASE_URL` и `SUPABASE_ANON_KEY` на значения из шага 3,
   `REDIRECT_TO` — на тот же адрес, что в шаге 4. Пока страница не
   отредактирована (плейсхолдеры `YOUR-PROJECT`/`YOUR-ANON` в конфиге),
   приложение работает в чисто локальном режиме, а индикатор в шапке
   показывает «Supabase не настроен».

6. **Задеплоить и проверить.** См. ниже. Открыть страницу, нажать «Войти»,
   ввести email, перейти по ссылке из письма — появится email и кнопка
   «Выйти», индикатор покажет «Синхронизировано».

Ключ `anon` — публичный по дизайну, его можно коммитить в репозиторий:
доступ к данным ограничивает RLS, а не секретность ключа. **Никогда не
используйте `service_role` ключ на клиенте.**

### Смена недели

Поле `week` в схеме уже общее — сейчас UI жёстко показывает одну неделю
(`CONFIG.WEEK` + `CONFIG.START` в `index.html`). Чтобы перейти на другую
неделю, поменяйте оба значения (это осознанно ручной шаг, переключение недель
в UI — отдельная будущая задача).

## Деплой на GitHub Pages

```bash
git push origin main
```

Затем в репозитории на GitHub: Settings → Pages → Source → Deploy from a
branch → branch `main`, папка `/ (root)`. Через минуту сайт будет доступен на
`https://<user>.github.io/<repo>/` — это и есть значение `REDIRECT_TO` в шаге
5 выше.

## Структура репозитория

```
index.html          — приложение целиком (HTML/CSS/JS), без каких-либо данных
supabase/schema.sql  — схема БД, RLS, триггер
docs/spec.md         — техническая спецификация синхронизации
CLAUDE.md            — заметки для работы с проектом через Claude Code
```

Роли, задачи и план в репозитории намеренно отсутствуют — это личные данные,
их вносит каждый пользователь сам через «Импорт JSON» после деплоя (а дальше,
при желании, через Supabase).

## Проверочный чек-лист

- [ ] Свежий деплой: палитра пуста, показывается подсказка про импорт.
- [ ] Импорт JSON с `roles` (+ опционально `blocks`) заполняет палитру и план.
- [ ] Без входа приложение работает локально, план и роли переживают перезагрузку.
- [ ] После входа план и роли заливаются на сервер — строки в `plans` и
      `role_configs` появляются.
- [ ] Вход с другого устройства тем же email подтягивает и план, и роли — без
      повторного импорта JSON.
- [ ] Изменение ролей или плана на устройстве A видно на устройстве B после
      перезагрузки или возврата вкладки в фокус.
- [ ] Выключенная сеть: правки не теряются, уходят на сервер после
      восстановления.
- [ ] Чужой пользователь не видит и не может изменить мои строки в `plans` и
      `role_configs` (RLS).
- [ ] Экспорт JSON отдаёт файл с `roles` и `blocks`, импорт этого же файла
      восстанавливает состояние.
